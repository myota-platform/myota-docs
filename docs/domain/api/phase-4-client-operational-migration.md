# Phase 4 — client and operations migration

**Status:** complete  
**Completed:** 2026-10-11  
**Scope:** canonical API clients, service route registries, contract mirrors,
and architecture/status documentation.

First-party clients now use the canonical resource and job operations. The
unused compatibility-only API aliases were removed from the service owners and
canonical OpenAPI contract. Intentional domain commands and job confirmation
operations remain explicit. No blanket conversion of commands into CRUD
operations was made.

## Client and contract ownership

- myota-contracts/contracts/openapi.yaml is the canonical HTTP contract.
- contracts/typescript/myotaClient.ts and
  contracts/python/myota_client.py are the lightweight typed client facades.
- Identity, Programme, Activity, and Geodata own their service handlers.
- Deploy owns runtime images and Helm; Platform contains synchronized
  integration copies.
- The Admin and public web clients use current contract operations. The
  Geodata-to-Activity deletion flow uses Activity-owned impact and cascade
  resources.

## Validation

The current Contract CI route inventory reports 132 OpenAPI operations and
170 registered service routes, with zero missing contract routes, zero
unregistered contract operations, and zero duplicate operation identifiers.
The checked-in route inventory is regenerated by CI, and the OpenAPI copy and
event schemas are compared with their Platform mirrors.

Repository searches of current Admin and public web source found no calls to
the removed compatibility-only aliases. Identity, Programme, Activity,
Geodata, Operations, Deploy, and Platform quality/build workflows pass at the
recorded source revisions. The Deploy image build and the Geodata service
image build pass.

Service HTTP metrics no longer include alias-specific request counters.
Operational guidance uses only current API resources, current audit commands,
and the current observability design.
